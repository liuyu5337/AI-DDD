# Documentation Standard

Technical documents should be:
- accurate
- structured
- concise
- implementation-aligned
- traceable to actual changes

Recommended sections:
- background
- scope
- design
- API impact
- SQL impact
- test impact
- deployment/rollback impact
- risks and limitations

Do not invent features or behavior.
